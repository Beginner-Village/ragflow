# RAGFlow + Coze-Studio 跨系统用户认证完整方案

## 📋 方案概述

本方案实现了RAGFlow和Coze-Studio之间的无缝用户认证，允许用户使用Coze-Studio的Cookie直接访问RAGFlow系统，无需重新登录。

## 🔧 已实现功能

### 1. 跨系统认证机制
- **Cookie认证**：支持`session_key` cookie自动认证
- **用户映射**：Coze用户ID通过MD5映射到RAGFlow用户ID
- **后向兼容**：保持原有RAGFlow认证机制不变

### 2. 数据库架构
- **视图系统**：创建`ragflow_tenant`、`ragflow_user`等视图映射Coze数据
- **配置表**：新增`ragflow_tenant_config`真实表存储可更新配置
- **权限系统**：完整的用户-租户关系和知识库权限控制

### 3. 服务层优化
- **TenantService**：智能选择配置数据源（配置表优先，视图后备）
- **TenantConfigService**：专门处理租户配置的CRUD操作
- **权限验证**：完整的知识库访问权限检查

## 🚀 核心组件

### 认证流程
```
1. 浏览器发送request with session_key cookie
2. load_user()检测到session_key
3. CozeAuthHelper.parse_session_key()解析用户信息
4. CozeAuthHelper.get_user_by_coze_id()映射到RAGFlow用户
5. 返回authenticated user对象
```

### 数据流向
```
Coze用户 → session_key → 解析用户ID → MD5映射 → RAGFlow用户 → 权限检查 → 访问资源
```

### 2. 主认证入口 `/api/apps/__init__.py`
```python
@login_manager.request_loader
def load_user(web_request):
    # 1. Coze cookie认证
    coze_session_token = web_request.cookies.get("session_key")
    if coze_session_token:
        user = CozeAuthHelper.authenticate_user(coze_session_token)
        if user:
            return user

    # 2. 传统Authorization header认证
    # ...
```

## 🐛 常见问题

### 1. 知识库ID错误
- **问题**：URL中的知识库ID拼写错误
- **解决**：检查正确的知识库ID，注意字符差异

### 2. session_key解析失败
- **问题**：Base64解析错误
- **解决**：检查cookie格式，确保完整性

### 3. 权限检查失败
- **问题**：UserTenant关系缺失
- **解决**：确保数据迁移完整，用户租户关系正确
